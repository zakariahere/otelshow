Devs will ask 'why HTTP and not gRPC here?' - fair question since the app->collector hop IS gRPC (4317). Answer: inside a compose network either works; we chose otlp_http into LGTM because HTTP/1.1 is the friendlier default through proxies and the LGTM image documents those endpoints. The deeper point for DevOps: modern backends grew native OTLP doors (Loki and Prometheus both ingest OTLP directly now), which kills a whole class of translation exporters. Remote write survives where Prometheus-native tooling is entrenched. Rule of thumb in the verdict.
