The receiver is Prometheus, embedded

receivers:
  prometheus:
    config:              # literally Prometheus scrape config      scrape_configs:
        - job_name: otelshow-app
          scrape_interval: 5s
          metrics_path: /actuator/prometheus
          static_configs:
            - targets: ["app:8080"]
exporters:
  debug:
    verbosity: detailed
service:
  pipelines:
    metrics:
      receivers: [prometheus]
      exporters: [debug]
  • The config: block is not “Prometheus-like”. It IS Prometheus scrape configuration — the receiver embeds Prometheus’s actual scrape engine.
  • Your existing scrape_configs, relabeling, service discovery: they paste straight in.
  • The pipeline wires it to debug and nothing else. No processors, on purpose.
Migration cost of the pull side: copy-paste. Everything the Prometheus admins know still applies.
